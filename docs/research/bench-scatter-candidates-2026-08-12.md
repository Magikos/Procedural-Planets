## Follow-up

**Keep means "earns a place in the repo", not "replaces the Meadow Tree."** Bryan's intent is
additive: widen the set of tree types that can spawn, leaving the existing Synty trees in place.
Promotion only moves the FBX out of `Assets/_Bench/` — it changes nothing about what spawns.

Outstanding work before either tree can actually be planted:

- **Author a `ScatterPrototype` per tree.** Parts are `(material + LOD mesh chain)`, not prefabs —
  trunk and canopy are separate parts, as the Meadow Tree is.
- **Free slot ids exist but the Inspector could not reach them.** 69 prototypes occupy slots 0–68;
  `ScatterId.MaxSlot` is 127, yet `ScatterPrototype.SlotId` still carried `[Range(0, 63)]` from
  before `SlotBits` went 6→7. Every reachable value was already taken, so a new prototype would
  have silently collided on a persistence key. Fixed to `[Range(0, ScatterId.MaxSlot)]`; slots
  69–127 are now selectable.
- **Shader cost, and the real price of these two Keeps.** Both candidates use vendor toon shaders
  (`Toon/TFF_CustomToonOutline`, `Toon/TEM_CustomVegetation`). The scatter pipeline expects
  `Scatter/FoliageLit`, which reads the planet's sun globals — vendor shaders do not, so these
  trees would stay lit on the night side. Either port them to `Scatter/FoliageLit` or fold the
  toon outline into it.
- **TEM trees ship no LODGroups**, so LOD chains have to be authored or generated by hand.

Judged against `Meadow Tree Prototype` (`SM_Env_Tree_Meadow_01`, trunk + canopy, `Scatter/FoliageLit`).
An earlier run the same day used `SM_Gen_Env_Tree_01` from the PolygonGeneric filler pack — a
trunk-plus-sphere with no texture assigned — which was not a fair comparand. That run is superseded.
