# NPC jobs and simulation detail

Status: fish job rollout and creature detail policy implemented and validated.
Bryan approved implementation on 2026-09-10. The Rivers task owns its visual changes and shares Unity through explicit handoffs.

## Execution and ownership

`FishSimulationJob` schedules one parallel iteration per school. Each school owns a disjoint range of fish state.
The school algorithm remains sequential internally because steering can change its shared heading.
Managed fixtures and jobs invoke the same `FishSimulation` algorithm and `FishMovement` habitat rules.
Swimming jobs use strict, high-precision floating-point calculations. Their habitat checks reserve a small planet-scale rounding margin.
This prevents sub-millimetre backend differences from admitting a position inside the required bed clearance.

`FishSimulationJobs` retains native buffers across frames. It schedules after collecting inputs and consumes completed results on a later tick.
The main thread does not wait for unfinished gameplay batches. A slow batch retains the previous published positions.
Runtime catch-up remains bounded at 0.1 seconds. Offline `FishSchool.Tick` retains explicit elapsed-time simulation.

Water queries use `WaterQueryKernel` for both managed and native inputs. `SurfaceQueryJobData` reuses existing noise, diagnostic-terrain, and river evaluators.
The snapshot owns copied water grids and terrain parameters. The planet owns river arrays.
`WaterQueryService` tracks reader handles and a configuration version. Reset completes readers before the planet releases river data.
Completed batches from an older configuration do not publish. Fish population clear completes pending work before releasing native buffers.
Planet regeneration clears fish before disposing terrain and river resources.

Threat selection remains on the main thread because it queries the current terrain mesh and live registries.
Jobs receive per-fish threat snapshots. The selected threat remains fixed during that batch's substeps.
This introduces a bounded snapshot delay instead of reading mutable world state from a worker.
Rendering, registry updates, spawning, and gameplay side effects remain on the main thread.

## Creature detail

The existing `CreatureResidencyService` owns all levels. No second NPC manager or EventBus scheduler was added.

| Level | Behavior |
|---|---|
| Full | Existing movement, decisions, and perception cadence. Combat and interactions override distance. |
| Reduced | Distant uninvolved residents keep per-frame movement and decisions. Ecology perception scans run every second instead of every half-second. |
| Coarse | Existing stored identity and behavior survive demotion. Promotion advances offline endurance and travel from elapsed absence. |

Full detail exits beyond 100 metres and re-enters within 80 metres. Returning to full detail forces a fresh perception scan.
An active chase, escape, combat action, feeding, drinking, or damage alarm prevents distance-only demotion.
Coarse state uses elapsed-time evaluation instead of polling every absent creature on a worker.
Creature brains and movement controllers remain managed. This change does not claim to move all animal AI into Burst.
Townsfolk schedules remain future gameplay scope.

## Verification

Core and Planet builds passed with zero errors. Planet retains 19 existing warnings.
The final combined EditMode batch passed 130 tests, including native/managed fish parity, a rounding-boundary case, habitat rules, creature residency, detail policy, and river regressions.
The job uses synchronous Burst compilation in the Editor so job tests exercise compilation before execution.
The initial new test file had CS1654 errors from writes through readonly using variables; those errors were corrected before the passing runs.

The final live window used seed `1691104419` at `RiverChannelFinal`, with seven schools and 42 fish.

| Measurement | Final result |
|---|---:|
| Completed batches / observed frames | 240 / 240 |
| Fish main-thread average / p95 | 0.105 / 0.148 ms |
| Actual frame interval average / maximum | 19.65 / 34.11 ms |
| CPU frame average / p95, last 120 samples | 19.24 / 24.34 ms |
| GPU frame average, 93 valid samples | 17.52 ms |

Before jobs, fish main-thread work averaged 5.88 ms with 44 fish. River visuals and populations changed between captures.
The comparison demonstrates main-thread offload; it is not an equal-count total-CPU benchmark or a guaranteed frame-rate gain.
The final run completed 840 managed habitat checks over 600 frames with zero failures.

The shared managed/native-input water kernel agreed exactly in 1,024 queries. Actual Burst water samples at 290 fish clearance points had zero body/hit mismatches.
Maximum Burst depth difference was 0.977 mm. A separate long observation exposed a 0.684 mm bed-clearance discrepancy, which led to the conservative rounding margin.
That margin's boundary test passes, and the final 600-frame habitat observation follows the fix.

A live isolated job owner passed reset invalidation and disposal with a pending batch. Neither operation published a stale result.
Exiting Play mode after the final run produced no observed job disposal, native memory, or exception errors in the Editor log tail.
Full evidence and build logs are in `local-only/npc-jobs/`.

## Next decisions

Native perception needs a safe snapshot of the exact terrain query used by gameplay. An analytic approximation must not silently replace mesh-based visibility.
Profile that stage before moving it. Keep gameplay outcomes on the main thread after accepting results for the current world and entity.
Use `JobHandle` dependencies for calculation ordering. Use EventBus for gameplay outcomes, rather than one event per calculation.
