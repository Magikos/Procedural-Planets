## 🔴 Bugs & Definite Defects

### BUG-01 — `DestroyImmediate` used in runtime code

**File:** `Assets/Scripts/Planet/Planet.cs` — `DestroyChildrenImmediate()`

```csharp
void DestroyChildrenImmediate()
{
    for (int i = transform.childCount - 1; i >= 0; i--)
        DestroyImmediate(transform.GetChild(i).gameObject);
}
```

`DestroyImmediate` is unsafe in Play mode — Unity explicitly warns against it for scene objects at runtime. It bypasses the normal one-frame deferred destruction lifecycle and can corrupt the scene hierarchy if called during rendering or physics. In Play mode this should be `Destroy()`.

**Fix:**

```csharp
void DestroyChildrenImmediate()
{
    for (int i = transform.childCount - 1; i >= 0; i--)
    {
#if UNITY_EDITOR
        if (!Application.isPlaying)
            DestroyImmediate(transform.GetChild(i).gameObject);
        else
#endif
            Destroy(transform.GetChild(i).gameObject);
    }
}
```

### BUG-02 — `TestPoissonDiscSphereDraw.Generate()` has a race condition

**File:** `Assets/Scripts/TestPoissonDiscSphereDraw.cs`

```csharp
public void Generate()
{
    planet.GeneratePlanetAsync();          // async void — returns immediately
    _points = PoissonDiscSphereSampling.GeneratePoints(
        minDistance, maxAttempts,
        planet.ShapeGenerator,             // ShapeGenerator is being mutated concurrently
        seed, BiomeSelector);
}
```

`GeneratePlanetAsync()` is `async void` and dispatches `Parallel.For` mesh generation to background threads after the synchronous `Initialize()`. The `ShapeGenerator` is initialized before the first `await`, so the noise filter reference itself is safe, but `_elevationMinMax` inside `ShapeGenerator` is being written by background threads (`CalculateMeshData → EvaluateElevation → AddValue`) at the same time `PoissonDiscSphereSampling` is also calling `EvaluateElevation` on the main thread. While `MinMax` is individually thread-safe, the concurrent access doubles the evaluation cost and produces a mixed min/max state that may not correspond to either run.

**Fix:** Either await generation before sampling (expose a `Task`/`Awaitable`-returning version of `GeneratePlanetAsync`) or call `GeneratePoints` only after the `PlanetGeneratedEvent` fires.

## 🟠 Architecture Violations

### ARCH-01 — Concrete type registered and retrieved through ServiceLocator, bypassing interfaces

**Files:** `Planet.cs`, `CelestialManager.cs`, `AtmosphereController.cs`, `CloudController.cs`, `WeatherManager.cs`

Multiple systems register and/or retrieve **concrete types** through the ServiceLocator instead of interfaces:

| Registrant                | Registers                                        | Consumer                                        | Retrieves                               |
| ------------------------- | ------------------------------------------------ | ----------------------------------------------- | --------------------------------------- |
| `Planet.Awake()`          | `ServiceLocator.Register<Planet>(this)`          | `CelestialManager.Initialize()`                 | `ServiceLocator.Get<Planet>()`          |
| `Planet.Awake()`          | `ServiceLocator.Register<Planet>(this)`          | `AtmosphereController.InitializeDependencies()` | `ServiceLocator.Get<Planet>()`          |
| `CloudController.Awake()` | `ServiceLocator.Register<CloudController>(this)` | Various                                         | `ServiceLocator.Get<CloudController>()` |
| `WeatherManager.Awake()`  | `ServiceLocator.Register<WeatherManager>(this)`  | Various                                         | `ServiceLocator.Get<WeatherManager>()`  |

**Architecture rule:** "Every system is behind an interface. Swap implementations without touching consumers."

`CelestialManager` only needs `_planetRadius`, which it could get from `PlanetGeneratedEvent`. `AtmosphereController` does the same. Both already subscribe to `PlanetGeneratedEvent` — they should derive all planet data from the event and not hold a `Planet` reference at all.

`CloudController` has no interface defined for it; one should be introduced (`ICloudController`), or the registration removed if no other system consumes it.

**Fix for `CelestialManager` and `AtmosphereController`:** Remove `ServiceLocator.Get<Planet>()` calls. Derive planet position/seed/radius exclusively from `PlanetGeneratedEvent` data that's already captured.  
**Fix for `CloudController`/`WeatherManager`:** If multiple consumers exist, define `ICloudController`/use existing `IWeatherProvider` consistently, and drop concrete registrations.

### ARCH-02 — `ITerrainProvider` and `IBiomeProvider` interfaces are incomplete

**Files:** `Assets/Scripts/Core/Interfaces/ITerrainProvider.cs`, `IBiomeProvider.cs`

Both interfaces define only `Initialize(int seed)` but not the mandatory `Configure()` setup step. `ShapeGenerator` requires `Configure(ShapeSettings)` before `Initialize(int)`, and `ColorGenerator` requires `Configure(BiomeSettings)`. Consumers using only the interface cannot set up the object correctly — they are forced to know about the concrete type, breaking the interface-driven principle.

**Fix:** Add `Configure` overloads to the interfaces, or use constructor injection to make the dependency explicit and remove the two-step init:

```csharp
public interface ITerrainProvider
{
    void Initialize(ShapeSettings settings, int seed);   // merged
    float EvaluateElevation(Vector3 pointOnUnitSphere);
    float GetScaledElevation(float unscaledElevation);
    float ElevationMin { get; }
    float ElevationMax { get; }
}
```

### ARCH-03 — `EventBus<T>` static state is never cleared on scene reload

**File:** `Assets/Scripts/Core/Events/EventBus.cs`

All `EventBus<TEvent>` generic instantiations hold static `_subscribers` and `_deferredQueue` lists. These survive scene loads. `GameBootstrap.OnDestroy()` calls `ServiceLocator.Clear()` but does **not** call `EventBus<T>.ClearAll()` for any event type. On scene reload, previously subscribed objects that have been destroyed will linger as dead weak references until the next event dispatch, but newly created subscribers may double-register if `OnEnable` fires again.

**Fix:** In `GameBootstrap.OnDestroy()`, call `ClearAll()` for all known event types:

```csharp
void OnDestroy()
{
    EventBus<PlanetGeneratedEvent>.ClearAll();
    EventBus<DayNightChangedEvent>.ClearAll();
    EventBus<MoonPhaseChangedEvent>.ClearAll();
    // ... or maintain a registry of all bus types to clear
    ServiceLocator.Clear();
}
```

A cleaner long-term fix is a typed registry of bus-clear delegates populated at registration time.

### ARCH-04 — `DebugCommandProvider` is a POCO that subscribes to EventBus without lifecycle cleanup

**File:** `Assets/Scripts/Core/Services/DebugCommandProvider.cs`

```csharp
public DebugCommandProvider()
{
    EventBus<DebugCommandRequestedEvent>.Listen(OnDebugCommandRequested);
    // Never unlistens
}
```

`DebugCommandProvider` is a plain C# class (not a MonoBehaviour). It subscribes to the EventBus in its constructor but has no `Dispose()` or `Unregister()` path. When `ServiceLocator.Clear()` drops the reference, the EventBus weak-reference will eventually die via GC — but the timing is non-deterministic. Between scene teardown and GC, the provider may continue receiving and re-dispatching events into already-destroyed systems.

**Fix:** Implement `IDisposable`, call `EventBus<DebugCommandRequestedEvent>.Unlisten(OnDebugCommandRequested)` in `Dispose()`, and call `Dispose()` from `GameBootstrap.OnDestroy()` before `ServiceLocator.Clear()`.

### ARCH-05 — `EventBusProcessor` uses a Singleton pattern

**File:** `Assets/Scripts/Core/Events/EventBusProcessor.cs`

```csharp
static EventBusProcessor _instance;

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
static void Init() { var go = new GameObject("[EventBusProcessor]"); go.AddComponent<EventBusProcessor>(); }
```

The architecture document states: "Dependency Injection — No singletons, no static god-classes." `EventBusProcessor` is self-creating and uses `DontDestroyOnLoad`, making it an implicit singleton. This is an infrastructure exception, but the processor list (`_processors`) is a static shared list that is never cleared. If a new game session or scene reset calls `RegisterProcessor` again, duplicate processors accumulate.

**Fix (minimal):** Add a `ClearProcessors()` static method and call it from `GameBootstrap.OnDestroy()`.

## 🟡 Code Quality & Checklist Violations

### QUAL-01 — `async void GeneratePlanetAsync()` prevents callers from awaiting or observing completion

**File:** `Assets/Scripts/Planet/Planet.cs`

```csharp
public async void GeneratePlanetAsync()
```

`async void` methods cannot be awaited by callers, meaning any code that calls `GeneratePlanetAsync()` and then immediately reads planet state (e.g., `TestPoissonDiscSphereDraw.Generate()`) cannot know when generation is complete. It also means fire-and-forget exception propagation if the internal `try/catch` is ever incomplete.

**Fix:** Change the signature to return `Awaitable` and expose the in-progress state cleanly. Callers that trigger it from non-async contexts (`Start()`) should use:

```csharp
public async Awaitable GeneratePlanetAsync()
{
    // same body
}

void Start() => _ = GeneratePlanetAsync();  // discard is intentional and visible
```

### QUAL-02 — `Shader.Find()` called during generation (should be cached)

**File:** `Assets/Scripts/Planet/Planet.cs` — `ConfigureMaterial()` and `CreateWaterMaterial()`

```csharp
var vcShader = Shader.Find("Planet/VertexColor");   // ConfigureMaterial
var shader   = Shader.Find("Planet/Ocean");          // CreateWaterMaterial
```

The code-health checklist states: "No Shader.Find in hot paths (cache references)." While these are not in `Update()`, they run on every `GeneratePlanetAsync()` call (including editor regenerations). The shader references should be cached as static fields initialized on first use, or assigned in the Inspector.

**Fix:**

```csharp
static Shader _vertexColorShader;
static Shader _oceanShader;

static Shader VertexColorShader => _vertexColorShader != null
    ? _vertexColorShader
    : _vertexColorShader = Shader.Find("Planet/VertexColor");
```

Every other controller in the codebase caches `Shader.PropertyToID` in `static readonly int` fields. Using string literals performs a hash lookup every call. ## ⚪ Improvement Suggestions

### SUGG-01 — `EventBusAutoBinder` uses reflection at bind time; consider caching

**File:** `Assets/Scripts/Core/Events/EventBusAutoBinder.cs`

`BindOrUnbind` calls `type.GetMethods(BindingFlags.Instance | BindingFlags.NonPublic | BindingFlags.Public)` and scans all attributes on every call. For MonoBehaviours that bind/unbind frequently (e.g., OnEnable/OnDisable during scene transitions), this creates repeated reflection GC pressure.

**Suggestion:** Cache the list of `(MethodInfo, HandleEventBusAttribute)` pairs per `Type` in a `static Dictionary<Type, ...>` so subsequent `Bind`/`Unbind` calls for the same type reuse the cached list.

### SUGG-02 — `ServiceLocator` could use `IDisposable` pattern for registered objects

**File:** `Assets/Scripts/Core/Services/ServiceLocator.cs`

When `ServiceLocator.Clear()` is called, registered objects that implement `IDisposable` are not disposed. `DebugCommandProvider` should implement `IDisposable`, but `Clear()` doesn't know to call it.

**Suggestion:** Add a `Clear()` variant that disposes `IDisposable` services:

```csharp
public static void Clear()
{
    foreach (var service in _services.Values)
        if (service is IDisposable disposable)
            disposable.Dispose();
    _services.Clear();
}
```

---

### SUGG-03 — `NoiseFilterFactory.CreateNoiseFilter` should use `switch` expression

**File:** `Assets/Scripts/Planet/NoiseFilters/NoiseFilterFactory.cs`

The current `switch` statement style is from older C# conventions. The project targets C# 9+ (Unity 6). A switch expression is more idiomatic and removes dead fall-through risk:

```csharp
return settings.Filter switch
{
    NoiseSettings.FilterType.Simple => new SimpleNoiseFilter(settings, seed),
    NoiseSettings.FilterType.Rigid  => new RigidNoiseFilter(settings, seed),
    _ => throw new ArgumentException($"Unknown filter type: {settings.Filter}")
};
```

### SUGG-04 — Unscaled MinMax reset happens on every `Initialize()` call; elevation range includes in-progress values

**File:** `Assets/Scripts/Planet/ShapeGenerator.cs`

`Initialize()` creates a new `MinMax`. Background threads then populate it via `Parallel.For`. If generation is cancelled mid-flight, the partial `_elevationMinMax` values remain accessible through `ElevationMin`/`ElevationMax` properties. Any consumer reading these before `PlanetGeneratedEvent` fires gets an incomplete range.

**Suggestion:** Use a local `MinMax` inside `CalculateMeshData` (or propagate it as a return value from the parallel work), then commit the final value to `ShapeGenerator._elevationMinMax` atomically only after all background work completes.
